## 一、测试结论总览

核心业务闭环（发布 → 审核 → 接单 → 执行 → 凭证 → 双确认 → 评价 → 结算，以及仲裁分支）**整体可正常走通**。历史问题报告（P0-01~P2-12、F1-F26）中的绝大多数修复项经实测确认已落地。本次实测新发现问题 **8 项**：P1×2、P2×2、P3×4。

### 已实测确认正常的重点项（节选）

| 类别 | 验证结果 |

## 二、问题清单

### P1-01 · 双确认完成顺序限制仅靠前端，后端未强制（资损风险）

- **问题描述**：设计规则为"接单方必须先提交凭证确认完成，发布者才能确认"（见 change_log 2026-06-08）。实测后端 **不校验此顺序**：发布者可在接单方未提交任何凭证时直接 `PUT /api/v1/orders/{id}` 确认成功（返回 200，时间线记录 `REQUESTER_CONFIRMED_COMPLETION`）。此后接单方一提交凭证，订单**立即自动完成并转账**——发布者失去查验凭证后再决定的机会，悬赏金未经发布者实质审核即转移。
- **复现步骤**：
  1. 发布者发布需求 → 管理员审核通过 → 接单方接单并"开始执行"（订单 IN_PROGRESS，`proofSubmitted=false`）；
  2. 发布者直接调用 `PUT /api/v1/orders/{orderId}`，body `{"targetStatus":"COMPLETED","note":"抢先确认"}` → 返回 200（应拒绝）；
  3. 接单方随后提交凭证完成 → 订单瞬间 COMPLETED，报酬转移。
  （实测订单 3、订单 4 均复现，订单时间线 15:25:39 的 `REQUESTER_CONFIRMED_COMPLETION` 早于凭证提交。）
- **涉及角色/页面**：发布者、接单方；订单详情页（`/demands/{id}`、`/orders/{id}`）；后端 `OrderApplicationServiceImpl`。
- **改进建议**：后端在发布者确认完成分支增加前置校验：`providerConfirmed && proofSubmitted` 不满足时返回业务冲突（如"接单方尚未提交完成凭证"），与前端按钮显示逻辑对齐；补充对应单元测试（requester-first confirm 必须失败）。

### P1-02 · README 测试账号与实际不符，演示 admin 账号无法登录

- **问题描述**：README「测试账号」表格列出"admin / admin@campushub.local / Admin1234 / 管理员"，实测该账号登录失败（`AUTH_FAILED`）；学号 `admin` 也不存在。实际可用的管理员是建表脚本的 **ADMIN001 / Admin123!**。按 README 操作的新成员/评审演示会被阻断。
- **复现步骤**：`POST /api/v1/auth/login`，body `{"loginId":"admin@campushub.local","password":"Admin1234"}` → `{"code":1001,"errorCode":"AUTH_FAILED"}`；换 `loginId:"admin"` 同样失败。
- **涉及角色/页面**：管理员；README 文档、登录页 `/auth`。
- **改进建议**：二选一——① 修正 README 测试账号表（管理员行改为 ADMIN001 / admin@edu.cn / Admin123!）；② 让 `DemoDataInitializer` 真正创建 admin@campushub.local 账号（当前该账号未落库，疑似 demo-data 开关或初始化逻辑失效，需一并排查）。

### P2-01 · 过期需求滞留审核队列：占用冻结资金、状态不流转

- **问题描述**：需求 `endTime` 已过但未审核时：① 管理员待审队列仍显示该需求并可"通过/拒绝"；② 发布者"我发布的需求（审核中）"区块仍显示"等待管理员审核"，无过期提示；③ 该需求冻结的报酬持续占用（实测 ¥2 长期冻结，可用余额被压低）；④ DB 中状态仍为 REVIEWING，未流转为 EXPIRED（公开列表与接单有按时间兜底过滤，用户侧风险已被兜住，但数据层不一致）。
- **复现步骤**：
  1. 发布报酬 ¥2 的需求 → 不审核 → 将 `ord_demand.end_time` 改为过去（或等待到期）；
  2. 管理员后台「待审核需求」仍出现该卡片（实测需求 id=10 仍在队列 `[10]`）；
  3. 发布者个人中心可用余额显示被扣除冻结金额（¥88 = 90 - 2）。
- **涉及角色/页面**：管理员（审核队列 `/admin`）、发布者（订单页"我发布的需求"、个人中心余额）；后端定时任务缺失。
- **改进建议**：增加定时任务将 `end_time < now` 且状态 ∈ {PENDING, REVIEWING} 的需求流转为 EXPIRED 并解冻资金；审核队列接口默认排除已过期项；发布者侧对过期需求显示"已过期，等待审核将自动失效"。

### P2-02 · 后端错误消息全英文，前端翻译覆盖面未知

- **问题描述**：后端所有业务错误均为英文（`user has been banned`、`demand has expired`、`proofImageUrls must contain 1 to 3 images`、`only in progress orders can be completed` 等）。实测登录路径的错误已被前端汉化（"学号或密码错误"✓），但订单操作失败、封禁提示等场景依赖前端 `errorHandler` 映射表逐条覆盖，存在漏网风险（例如：对已完成订单重复确认时前端是否翻译未经逐一验证）。
- **复现步骤**：API 层任意触发业务错误，如 `POST /api/v1/orders/{id}/reviews` 重复评价、封禁用户登录，响应 message 均为英文原文。
- **涉及角色/页面**：全部角色；前端 `utils/errorHandler.ts`。
- **改进建议**：以 `errorCode`（AUTH_FAILED/PERMISSION_DENIED/VALIDATION_FAILED/BUSINESS_CONFLICT）为一级映射、message 关键字为二级兜底，确保未覆盖错误至少有"操作失败，请稍后重试"类的中文兜底提示；补一条 E2E 断言防止回归。

### P3-01 · 需求列表筛选器文案误用"订单"字样

- **问题描述**：`/demands` 筛选区标签为"订单分类""订单状态""订单排序"，但页面是**需求**列表，术语混淆（同页面下方又是"需求列表"标题）。
- **复现步骤**：游客或任意登录用户访问首页 `/demands`，查看筛选栏。
- **涉及角色/页面**：全部角色；`DemandListView.vue`。
- **改进建议**：改为"需求分类""需求状态""需求排序"；全局排查"订单/需求"术语混用。

### P3-02 · 浏览器标签页标题为默认值 "frontend"

- **问题描述**：所有页面 `<title>` 均为 Vite 脚手架默认的 "frontend"，多标签使用与品牌辨识度差。
- **复现步骤**：打开 `http://localhost:5173/`，查看浏览器标签页。
- **改进建议**：`index.html` 改为 "CampusHub - 南京大学校园互助平台"，并可在路由钩子按页面动态设置。

### P3-03 · 游客顶栏显示无意义的"未读消息 0"入口

- **问题描述**：未登录时顶栏右侧仍显示"未读消息 0"，点击才跳转登录页；对游客是无效信息。
- **复现步骤**：以游客访问任意页面，观察顶栏。
- **涉及角色/页面**：游客；`App.vue` 顶栏。
- **改进建议**：游客态隐藏该入口，或替换为"登录后查看消息"提示。

### P3-04 · 管理后台统计口径待复核

- **问题描述**：仪表盘"今日活跃用户"基于 `createdAt/updatedAt` 聚合（`后端待修复清单.md` 第 8 项已知差距），仅做资料修改而无真实行为的用户会被计入/漏计，口径偏弱。本次实测数值非零（3/7/1/3），功能可用，仅口径问题。
- **涉及角色/页面**：管理员；`/admin` 仪表盘、`AdminApplicationServiceImpl`。
- **改进建议**：接入登录日志或行为日志（`rec_user_action_log` 已有 VIEW/ACCEPT 行为）计算 DAU；与团队确认口径后更新文档。

## 三、测试环境备注（非缺陷，供团队参考）

1. **端口被环境变量劫持**：本机 shell 存在 `SERVER_PORT` 类环境变量注入现象时，Spring Boot 会忽略 `application.properties` 的 `server.port=8080`（实测 Tomcat 起在 13443），导致 Vite 代理（固定指向 8080）连不上、前端全部接口报错。启动脚本/start.sh 建议显式 `--server.port=8080` 兜底。若出现"后端明明在跑但前端代理 404/ECONNREFUSED"，优先检查后端实际监听端口。
2. **实测产生的数据**：本次测试在开发库中创建了需求 7~10、订单 3（已完成）、订单 4（已仲裁取消）、评价 2 条、新用户 NEWTEST01（余额 100）。其中需求 10（[测试4]过期验证）end_time 已被改为过去用于过期测试，可按需清理。
